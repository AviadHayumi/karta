Why we keep going up

We recognize Deployment, but it also has a parent. We keep going up and choose the highest workload that Karta recognizes: Dynamo in this example.

If we do not know a parent yet

We put the pod aside and remember which parent is missing. When that parent arrives, we try the pod again and finish following the chain.

What we save locally

We save the objects and their parent links. We also save what each workload requests and where each pod belongs. Prometheus keeps the history of the metric values.

Our example: dynamo-smoke requests 3 decode replicas and one pod is Pending. Some startup steps happen at the same time; we show one possible order. The change boxes at the end are separate examples, each starting from this state. The parent chain is a teaching example, not a check of your cluster.
